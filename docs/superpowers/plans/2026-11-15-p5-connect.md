# DAP MCP Service — Phase 1b: Connect Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpower-subagent-driven-development (recommended) or superpower-executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command connects DAP to Hermes and DSH: `dap-mcp install`, verified by `dap-mcp doctor`, shipped as a `dist/` artifact.

**Architecture:** A stdlib-only Python CLI (`adapters/mcp/dap_cli.py`) wraps the existing stdio server and edits client configs through a line-based YAML upsert helper (`adapters/mcp/mcp_config.py`). `doctor` preflights the server over stdio directly, so it does not depend on the client CLI being runnable.

**Tech Stack:** Python 3.10+ stdlib (no PyYAML), existing `adapters/mcp/dap_mcp.py`, Makefile, shell.

**Spec:** `docs/superpowers/specs/2026-11-15-dap-mcp-service-design.md`

## Global Constraints

- Python stdlib only; PyYAML is not installed and must not become a dependency.
- Client configs are edited with a backup, `--dry-run`, and a post-write parse check; no partial writes.
- Absolute paths in every generated entry: both clients scrub the child env.
- Commits: conventional, English. `make check` stays green.
- Worktree `.worktrees/p5-connect`, branch `p5/connect`.

## Review Focus

1. Config with existing unrelated MCP servers — install preserves them and only adds or updates `dap`.
2. DSH patch that already has an `mcp-manager` entry — `servers.dap` is merged, other keys stay.
3. Read-only or malformed config — install exits 2 with a printable fragment and writes nothing.
4. Client CLI missing or broken — `doctor` still verifies the server over stdio.
5. Re-running install twice — idempotent, one entry, unchanged mtime when nothing changed.
