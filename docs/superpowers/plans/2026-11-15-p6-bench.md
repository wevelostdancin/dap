1. tests/p6_bench.py — stdlib-only benchmark harness (urllib, subprocess, json, time, statistics, pathlib).

## Harness CLI

--timeout (per operation, default 900)
--mcp / --no-mcp

## Engine lifecycle

Start: java -Xmx<heap> -jar <jar> with env DAP_HOME=repo root, DAP_PORT, DAP_BIND=127.0.0.1,
DAP_DUCKDB_MEMORY_LIMIT (default 1GB), DAP_DUCKDB_TEMP_DIR=<out>/duckdb-tmp,
DAP_CACHE_DIR=<out>/cache, DAP_ALLOWED_ROOTS=<data-dir>:<out>:<repo>:/tmp.
Wait /v1/health. Capture stderr to <out>/engine.log. Stop with POST /v1/shutdown.

## Manifest

JSON array of objects:
{"name":"us-accidents","path":"/abs/file.csv","format":"csv",
 "sql":"SELECT ...","numeric_columns":["a","b"],"group_column":"state","value_column":"severity"}

## Per-dataset measurements (wall ms, response bytes, error)

- POST /v1/datasets ingest: rows, columns, cached, cache file bytes.
- Create workflow + dap.parquet_reader + run: plan/build time.
- GET /table?limit=20; GET /table?offset=1000&limit=20 (paging).
- GET /profile.
- POST /v1/explore {dataset: parquet path, sampleRows: 1000}.
- SQL aggregate through a temp workflow: parquet_reader -> sql_query (manifest sql or SELECT COUNT(*) AS n FROM src), run, /table.
- Optional correlation node on numeric_columns (>=2) and linear_regression if value/target is given.
- Engine RSS via ps -o rss= and /v1/health memory before/after heavy steps.

## MCP mode

Spawn adapters/mcp/dap_mcp.py with DAP_PORT/DAP_HOME, initialize, then call:
dap_explore, dap_analyze, dap_get_table (offset + columns + format csv), dap_estimate,
dap_report (format html). Record tool name, wall ms, response bytes, approx tokens (bytes/4),
call count. Compare one-call tools with the equivalent HTTP multi-step.

## Output

<out>/<dataset>.json, <out>/summary.json, <out>/summary.md.
If <data-dir>/reference.json exists (dataset -> {rows, numeric_means:{col:value}, group_counts:{...}}),
compare DAP profile/explore/table results and record absolute/relative diffs; otherwise skip with a note.

## Robustness

Per-step timeout; on timeout/error record and continue. Never hang the whole run.
